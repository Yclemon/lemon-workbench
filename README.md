# lemon-workbench

小工具、插件、MOD 的收纳柜。一个项目一个文件夹，平铺。

## 启动

双击根目录的 **`工作台.bat`**，会列出所有工具和它们的运行状态，选个数字就能启动。

不用记端口，不用开命令行，不用先 `cd` 进子目录。

## 项目

| 项目 | 一句话 | 状态 | 启动 |
|---|---|---|---|
| [steam-play](steam-play/) | 读取本机 Steam 存档，展示总时长、买了没打开、吃灰 ≥90 天、磁盘占用 | 可用 | 工作台选 `1`（端口 8770） |
| [oni-tools](oni-tools/) | 缺氧（眼冒金星 DLC）查询与测算：建筑速查、房间规划、制氧测算、供电测算，数据从游戏源码提取 | 可用 | 工作台选 `2`（端口 8781） |

> 加项目 = 加一个顶层文件夹 + 在下面这张表里加一行 + 在 `工作台.bat` 里加一个入口。

## 日记

`diary/` 目录，一天一个 `.md`（`diary/<年>/<月>/<YYYY-MM-DD>.md`），正文自己写。

### 躺着在手机上看

双击 `工作台.bat` 选 **`4`**，会起一个小服务并打印地址：

```
手机上看:   http://192.168.0.198:8788
```

手机连**同一个 WiFi**，把这个地址存成浏览器书签。电脑上写完日记，手机上刷新就看见，不用传、不用同步、不用装 App。

阅读页右上有个「复制全文」，点一下整篇就进了剪贴板，粘到 moom 这类 App 里正好。

> 服务只监听局域网（`0.0.0.0:8788`），没有对外开放的口子。关掉那个黑窗口 = 服务停止。

### 导成 txt 带走

手机不在同一个网的时候用这个：

```bash
python push_diary.py --txt          # 最新一篇 → diary-txt/<日期>.txt
python push_diary.py --all --txt    # 全部，额外生成 diary-txt/全部日记.txt
python push_diary.py --list         # 先看看有哪些
```

`diary-txt/` 已在 `.gitignore` 里，不进版本库。

### 微信推送（暂时用不了）

`push_diary.py` 不带参数就是走微信机器人直推。但微信有个硬限制：**bot 只能在你最近主动给它发过消息的窗口内推**。当前会话窗口是关的，直接调会拿到 `{"ret":-2,"errmsg":"prepare failed"}` —— 这是平台规则，不是工具坏了。

真要用：先在手机微信给机器人发一句「在吗」，再跑 `python push_diary.py`。

## 结构约定

- **每个项目一个顶层文件夹，平铺**，不建 `plugins/`、`mods/`、`tools/` 这类分类目录 —— 分类会变，改名会让 git 产生一堆 rename 噪音、链接全断。要分类用仓库的 **topics**。
- **每个项目必须自带 `README.md`**：干什么、怎么跑、依赖什么。
- **项目之间不许互相 import。** 一旦 A 依赖 B 的代码，要么合并，要么把 B 拆成独立仓库。
- **这个 README 是唯一索引。** 加项目 = 加文件夹 + 加一行表格。

## 什么时候该拆成独立仓库

撞到任何一条就拆：

1. 它要对外发布（别人要下载/安装这个插件或 MOD）—— 安装器和插件市场认的是仓库 URL。
2. 它需要自己的 CI，且跑一次很贵 —— 不然每次 push 都会触发全部 workflow。
3. 别人要单独 fork / 提 issue —— 贡献者不该被强迫下载全部项目。

拆分方式（历史能保住）：

```bash
git subtree split --prefix=<项目名> -b <项目名>-standalone
```
