# lemon-workbench

小工具、插件、MOD 的收纳柜。一个项目一个文件夹，平铺。

## 项目

| 项目 | 一句话 | 状态 |
|---|---|---|
| [steam-play](steam-play/) | 读取本机 Steam 存档，展示总时长、买了没打开、吃灰 ≥90 天、磁盘占用 | 可用 |

> 加项目 = 加一个顶层文件夹 + 在下面这张表里加一行。

## 结构约定

- **每个项目一个顶层文件夹，平铺**，不建 `plugins/`、`mods/`、`tools/` 这类分类目录 —— 分类会变，改名会让 git 产生一堆 rename 噪音、链接全断。要分类用仓库的 **topics**。
- **每个项目必须自带 `README.md`**：干什么、怎么跑、依赖什么。
- **项目之间不许互相 import。** 一旦 A 依赖 B 的代码，要么合并，要么把 B 拆成独立仓库。
- **这个 README 是唯一索引。** 加项目 = 加文件夹 + 加一行表格。

## 什么时候该拆成独立仓库

撞到任何一条就拆：

1. 它要对外发布（别人要下载/安装这个插件或 MOD）—— 安装器和插件市场认的是仓库 URL。
2. 它需要自己的 CI，且跑一次很贵 —— 不然每次 push 都会触发全部 workflow。
3. 别人要单独 fork / 提 issue —— 贡献者不该被强迫下载全部项目。

拆分方式（历史能保住）：

```bash
git subtree split --prefix=<项目名> -b <项目名>-standalone
```
